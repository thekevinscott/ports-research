# 2026-09-28T09:47Z The /shared layout is asserted per condition through real rsync

PR #78. Kevin: "it may be worth bringing back tests on the Docker file; or
otherwise asserting that the various rsync rules do produce the layout of
files on disk we expect. This is really the whole shebang and what screwed
the v1 of the experiment, so it's important to get it right in the lowest
cost way we can."

The composer's unit test now mocks `compose` and only checks which rule
files are named in what order. That proves nothing about what rsync does
with them, and order is the whole mechanism: `source.rules` excludes tests,
and the test includes only win because they come first.

`layout_test.py` closes that gap without docker. `fixtures/<gbnf sha>.txt`
lists every file under `packages/gbnf` at pin 13f1aca once both integration
suites are generated (taken from the built image, node_modules omitted). The
test materialises that tree as empty files, composes the rules for each of
the sixteen conditions, runs `rsync -a --prune-empty-dirs --filter="merge"`
exactly as the Dockerfile does, and compares the listing to
`fixtures/shared/<condition>.txt`. It also asserts the fixture names the
pinned commit and that the Dockerfile still uses those rsync flags.

The sixteen listings were generated by the test's own rsync call, then three
were diffed against `find /shared` in real builds at the pin (python all-on,
python all-off, javascript all-on): identical. Putting `source` ahead of the
test includes in the composer fails twelve of sixteen, the four all-off
conditions being unaffected, which is the expected shape.

Kevin: "I think it _should_ be asserted through docker, no? Otherwise it's
testing theater?" The host test cannot see the build-arg transport, and that
is where a slip is likeliest. `tests/e2e/prepare_image_test.py` builds the
real image per condition and compares `find /shared` to the same sixteen
fixtures. 16 passed in 19s with warm layers. Replacing the Dockerfile's
quoted `printf` with an unquoted `echo` collapses the rules to one line and
fails with 235 extra files under `/shared`, `dev/` included. The host test
stays as the one-second check that points at the rule file; the e2e is the
ground truth.
