# GBNF (TypeScript)

A TypeScript port of `reference_implementation/` (the Python `gbnf` package): a library
for parsing `.gbnf` grammar files and walking the resulting grammar graph.

```ts
import { GBNF } from "gbnf";

let state = GBNF('root ::= "foo"');
state = state.add("f");
[...state]; // => [RuleChar { value: [111] }]  (the rules that may come next)
state.size; // => 1
```

## Layout

The port mirrors the Python package one file at a time; `snake_case` module names become
`kebab-case` file names, and `snake_case` functions become `camelCase`.

| Python                                        | TypeScript                                       |
| --------------------------------------------- | ------------------------------------------------ |
| `gbnf/GBNF.py`                                 | `src/gbnf.ts`                                     |
| `gbnf/__init__.py`                             | `src/index.ts`                                    |
| `gbnf/utils/is_point_in_range.py`              | `src/utils/is-point-in-range.ts`                  |
| `gbnf/utils/validate_non_empty.py`             | `src/utils/validate-non-empty.ts`                 |
| `gbnf/utils/errors/*.py`                       | `src/utils/errors/*.ts`                           |
| `gbnf/rules_builder/*.py`                      | `src/rules-builder/*.ts`                          |
| `gbnf/grammar_parser/build_rule_stack.py`      | `src/grammar-parser/build-rule-stack.ts`          |
| `gbnf/grammar_graph/*.py`                      | `src/grammar-graph/*.ts`                          |
| —                                              | `src/utils/code-points.ts` (see PORTING-NOTES.md) |

Python methods spelled `__like_this__` (which are not actually private in Python) are
plain public methods here: `Graph.__get_root_node__` → `Graph.getRootNode`,
`__get_initial_pointers__` → `getInitialPointers`, `__parse__` → `parse`,
`__resolve_pointer__` → `resolvePointer`, `__fetch_nodes_for_root_node__` →
`fetchNodesForRootNode`, `__iterate_over_pointers__` → `iterateOverPointers`.

Python's operator dunders have no JavaScript equivalent, so `ParseState.__call__` and
`ParseState.__add__` are both just `ParseState.add(text)`, and `__iter__` is
`[Symbol.iterator]`.

## Importing

The sources are TypeScript, and Node 24 runs them directly (type stripping). A generated
`.js` file sits next to every `.ts` file, forwarding to it, so `.js` specifiers resolve to
the very same module — mixing the two extensions never gives you two copies of a class.
All of these resolve to the same library:

```ts
import { GBNF } from "gbnf";                                  // package entry point
import { GBNF } from "../ported_implementation/index.ts";     // or index.js
import { GBNF } from "../ported_implementation/src/index.ts"; // or src/index.js
import { RuleChar } from "gbnf/grammar-graph/grammar-graph-types.ts";
```

`dist/` holds a self-contained, type-free copy of the library for toolchains that cannot
load TypeScript at all. Regenerate both after changing any source:

```bash
node scripts/build-js.mjs
```

### Compatibility layers

Since consumers may have been written against the Python package's module paths and
function names, three thin, generated compatibility layers exist. They all forward to
`src/`; there is only ever one implementation.

- `src/compat.ts` — `snake_case` aliases (`is_word_char` === `isWordChar`), re-exported
  from the package entry point.
- `gbnf/**` — the Python package's module layout
  (`gbnf/grammar_graph/graph_node.ts` → `src/grammar-graph/graph-node.ts`), regenerate with
  `node scripts/build-python-layout.mjs`.
- `dist/**` — the self-contained JavaScript build, for tooling that expects a `dist`
  directory or cannot load TypeScript.

## Tests

```bash
npm test            # node --test "test/*.test.ts"
```

- `test/differential.test.ts` compares the port against golden fixtures generated by
  running the Python reference implementation over 46 grammars, 36 input sequences and 15
  invalid grammars (`test/fixtures/reference.json`). Regenerate with
  `python3 scripts/generate_reference_fixture.py`.
- The remaining files are unit tests, one per module of the reference package.

See PORTING-NOTES.md for the handful of places where the port intentionally differs from
the reference implementation.
