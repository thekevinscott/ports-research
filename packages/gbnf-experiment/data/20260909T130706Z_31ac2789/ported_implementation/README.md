# GBNF (TypeScript)

A TypeScript port of `reference_implementation/` — a library for parsing `.gbnf` grammar files.

```ts
import GBNF from 'gbnf'; // or: import { GBNF } from '../ported_implementation/index.ts'

let state = GBNF('root ::= "foo"');
state = state.add('f');

for (const rule of state) {
  // RuleChar { type: 'char', value: [111] } — the characters that may come next
}
```

## Layout

The port mirrors the Python package file for file, so each module lines up with its
counterpart in `reference_implementation/gbnf/`:

| TypeScript | Python |
| --- | --- |
| `src/gbnf.ts` | `gbnf/GBNF.py` |
| `src/rules_builder/*` | `gbnf/rules_builder/*` |
| `src/grammar_parser/build_rule_stack.ts` | `gbnf/grammar_parser/build_rule_stack.py` |
| `src/grammar_graph/*` | `gbnf/grammar_graph/*` |
| `src/utils/*` | `gbnf/utils/*` |

`index.ts` re-exports the whole public surface; `GBNF` is also the default export.
Identifiers are camelCase (`parseChar`, `buildRuleStack`, `getSerializedRuleKey`), and every
function is additionally exported under its Python name (`parse_char`, `build_rule_stack`, …)
so code written against the reference's names keeps working.

## Tests

```bash
vitest run            # from the repository root, or from this directory
```

* `test/reference_parity.test.ts` — end-to-end parity. `test/fixtures/reference_fixtures.json`
  is generated by running 35 grammars (plus 12 malformed ones) through the *Python* reference
  and recording its rules, symbol ids, rule stacks, and the result of parsing ~39 inputs and 7
  incremental input sequences against each. The port must reproduce all of it.
* `test/reference_units.test.ts` — the same idea at the function level (`parseChar`,
  `parseSpace`, `parseName`, `buildErrorPosition`, `getSerializedRuleKey`, the printers, …),
  driven by `test/fixtures/unit_fixtures.json`.
* `test/api.test.ts` — the public API, written by hand.
* `test/resolution.test.ts` — the entry points resolve.

Regenerate the fixtures (requires Python 3.11+) with:

```bash
python3 test/fixtures/generate_fixtures.py
python3 test/fixtures/generate_unit_fixtures.py
```

## Differences from the reference

Behaviour is identical for well-formed grammars and inputs. The exceptions:

1. **Rule ordering.** The reference stores the nodes a rule reference points at in a Python
   `set`, whose iteration order is undefined, so the order rules come out of a parse state is
   arbitrary there. Backed by a JS `Set`, the port's order is stable (insertion order). Parity
   is therefore asserted on the *set* of rules.
2. **Errors from running off the end of the grammar.** For input like `root ::= "foo` (an
   unterminated string), `root ::= [a` or `root ::= ("a"`, the reference indexes past the end
   of the string and raises a bare `IndexError`; the port raises `GrammarParseError`
   ("Unexpected end of grammar input, failed to complete parse") pointing at the position.
   Likewise, a grammar with no `root` rule raises `KeyError: 'root'` in the reference and
   `GrammarParseError: Grammar does not contain a 'root' symbol` here — the message the
   reference's own code intends to raise.
3. **`rule.type`.** Rules carry a `type` field (`'char' | 'char_exclude' | 'end' | 'ref'`).
   The reference's printer reads `rule.type` too, but no such attribute exists there, so
   printing any graph containing an end rule raises `AttributeError`. Printing works here.
4. **Serialized rule keys.** `getSerializedRuleKey` uses `JSON.stringify`, so it emits
   `1-[[97,122]]` where Python's `json.dumps` emits `1-[[97, 122]]`. The key is only used to
   compare rules internally.
5. **String positions.** The reference indexes the grammar by code point; the port indexes it
   by UTF-16 code unit, which is identical for everything in the BMP, and `parseChar` treats a
   literal astral character (an emoji, say) as one character two units wide. Error messages
   still count columns in code points, so they line up with the reference's.
6. **`ParseState`.** Python's `state(text)` and `state + text` become `state.add(text)`;
   iteration (`for (const rule of state)`), `state.size` and `state.grammar` are unchanged.
