# GBNF (TypeScript port)

A TypeScript port of `reference_implementation/` (the Python `gbnf` package), a
library for parsing `.gbnf` grammars.

```ts
import { GBNF } from "gbnf";

let state = GBNF('root ::= "yes" | "no"');
state = state.add("y");
[...state]; // [ RuleChar(value=[101]) ] — the rules that may come next
state.size; // 1
```

## Layout

The module layout mirrors the reference one-to-one (file names are kebab-cased,
identifiers are camel-cased):

| Python                                   | TypeScript                                    |
| ---------------------------------------- | --------------------------------------------- |
| `gbnf/GBNF.py`                           | `src/GBNF.ts`                                 |
| `gbnf/rules_builder/*.py`                | `src/rules-builder/*.ts`                      |
| `gbnf/grammar_parser/build_rule_stack.py` | `src/grammar-parser/build-rule-stack.ts`      |
| `gbnf/grammar_graph/*.py`                | `src/grammar-graph/*.ts`                      |
| `gbnf/utils/**.py`                       | `src/utils/**.ts`                             |

## Tests

```bash
vitest run                 # from the repository root
```

`tests/fixtures/fixtures.json` is generated by running the Python reference over
a corpus of grammars and inputs — 36 hand-written cases, 240 seeded-random input
sequences, and 120 randomly mutated grammars that exercise the parser's error
paths — capturing its internal rules, rule stacks, per-chunk parse state and
errors (type and message). `tests/fixtures.test.ts` replays all of it against the port,
so the two implementations are compared directly rather than against
hand-written expectations. Regenerate with:

```bash
python3 tests/fixtures/generate_fixtures.py
```

`tests/units.test.ts` covers the individual modules and the public API surface.

## Porting notes

Behaviour is intended to match the reference exactly, including its quirks
(`RulesBuilder`'s time limit is still measured in seconds; `Graph` still
accumulates `previousCodePoints` across `add` calls so error positions grow with
the input; identical rules are still not de-duplicated in `Graph`).

Language differences that needed a decision:

- **Python builtins.** The reference raises `ValueError`, `KeyError` and
  `IndexError` for programmer/usage errors. `src/utils/errors/python-errors.ts`
  defines classes with the same names and messages, and `charAt` reproduces
  Python's out-of-bounds string indexing. So, as in the reference, a grammar
  without a `root` rule raises `KeyError('root')` (the "Grammar does not contain
  a 'root' symbol" branch in `GBNF.ts` is unreachable there too), and an
  unterminated string literal raises `IndexError`.
- **`str(error)`.** `GrammarParseError`/`InputParseError` override `toString()`
  to return the message alone, matching Python; `__eq__` becomes `equals()`.
- **Dunder methods.** `ParseState.__call__`/`__add__` have no TypeScript
  equivalent; use `state.add(text)`. `__eq__` on rules becomes `equals()`, and
  `__dict__` becomes `toDict()` (used, as in the reference, to de-duplicate the
  rules yielded by `ParseState`).
- **`Rule.type`.** `print.py` reads `rule.type`, which does not exist on the
  Python classes, so `Graph.print()` raises `AttributeError` there for any
  grammar. The port exposes `type` (the class name, matching what `__dict__`
  reports) so printing works; this is the one place the port deliberately
  behaves better than the reference.
- **Strings.** Python strings are sequences of code points. Input handling
  (`getInputAsCodePoints`) and error positions (`buildErrorPosition`) iterate by
  code point to match. Grammar *text* is indexed as UTF-16, as in the original
  TypeScript library this reference was itself ported from; that only differs
  for a literal non-BMP character written directly into a grammar (`\U0001F600`
  escapes are unaffected).
- **Types.** No `typescript` package is installed in this environment, so
  `tsconfig.json` is provided but the sources have not been run through `tsc`;
  tests execute via vitest's esbuild transform.
